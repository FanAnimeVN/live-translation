# Lightweight manga OCR comparator — primary-source review

Reviewed 2026-10-14. This review fetched public metadata/configuration/source text only. It did not download weights, execute remote Python, inspect private images or run a benchmark. The proposals below are comparators, not production defaults or redistribution clearance.

## Decision

**Try official `PaddlePaddle/PP-OCRv5_mobile_rec` using the already-installed Paddle runtime first**, on isolated lines/columns. The main agent reports PaddleOCR 3.7.0 / Paddle 3.3.1, Transformers 4.57.6 and no torchvision; avoid altering production packages. The safer future Transformers route is `PP-OCRv5_mobile_rec_safetensors`, with native implementations and no model-repository Python. Keep manga-ocr as the unchanged bubble baseline. [Owning native card](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec), [native Transformers documentation](https://huggingface.co/docs/transformers/en/model_doc/pp_ocrv5_mobile_rec).

Minimum native Transformers release is **5.4.0**, published 2026-03-27: that tag contains the model, recognition Auto task and processor mapping; 5.3.0 lacks them. Any future test uses a separate pinned environment, not `trust_remote_code=True` as a workaround. [5.4.0 release](https://github.com/huggingface/transformers/releases/tag/v5.4.0), [5.4.0 Auto task](https://github.com/huggingface/transformers/blob/v5.4.0/src/transformers/models/auto/modeling_auto.py), [5.3.0 Auto task](https://github.com/huggingface/transformers/blob/v5.3.0/src/transformers/models/auto/modeling_auto.py).

**Defer Hayai Nova loading.** It is a plausible manga-specialist comparator, but its published loader explicitly requires executable custom code, contrary to this project's inference rule. Safetensors alone does not remove that requirement. [Owning Nova card](https://huggingface.co/JustANormalTinkerer/hayai-ocr-v2.5-nova).

## PP recognizer: architecture and input contract

Mobile uses PPLCNetV3 scale 0.95, a two-layer SVTR recognition head (hidden size 120, eight attention heads) and 18,385 output classes. Training uses a CTC/NRTR multi-head; the reviewed native inference implementation emits class probabilities for CTC decoding, not autoregressive text generation. Server uses an HGNetV2-L backbone with the same configured head dimensions. [Mobile training configuration](https://github.com/PaddlePaddle/PaddleOCR/blob/main/configs/rec/PP-OCRv5/PP-OCRv5_mobile_rec.yml), [pinned native model source](https://github.com/huggingface/transformers/blob/28034545c35acac05793695bd5c878f66e6b544e/src/transformers/models/pp_ocrv5_mobile_rec/modeling_pp_ocrv5_mobile_rec.py), [pinned server configuration](https://huggingface.co/PaddlePaddle/PP-OCRv5_server_rec_safetensors/blob/542979d7cc3791732bb12af35313a6840952d79f/config.json).

Use `AutoModelForTextRecognition` and `AutoImageProcessor`, explicitly `trust_remote_code=False`, safetensors and CPU. Mobile maps to native `PPOCRV5MobileRecForTextRecognition` and `PPOCRV5ServerRecImageProcessor`; do not copy/download the optional repository `ocr_pipeline.py` into inference. The required model files are weights, `config.json` and `preprocessor_config.json`. [Native usage/classes](https://huggingface.co/docs/transformers/en/model_doc/pp_ocrv5_mobile_rec), [pinned processor mapping](https://github.com/huggingface/transformers/blob/28034545c35acac05793695bd5c878f66e6b544e/src/transformers/models/auto/image_processing_auto.py).

The native processor converts RGB, rescales by 1/255 and normalizes with mean/std 0.5. It resizes to height 48, aspect-derived width capped at 3,200, and pads to width 320 if shorter. It decodes its 18,385-entry character list by dropping CTC blanks/adjacent repeats; the score is average selected probability, **not a calibrated correctness probability**. It does not split balloons or rotate tall text. Its batch width calculation uses the widest pixel-width image, so begin with batch size one rather than mixing aspect ratios. [Pinned processor config](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec_safetensors/blob/485a9a9781535ad477de3b1eea5f96a2e7300d8d/preprocessor_config.json), [pinned native processor source](https://github.com/huggingface/transformers/blob/28034545c35acac05793695bd5c878f66e6b544e/src/transformers/models/pp_ocrv5_server_rec/image_processing_pp_ocrv5_server_rec.py).

Japanese/vertical-text support is an author claim, not demonstrated on our pages. The owning example full-page pipeline rotates a crop with height/width >= 1.5 using `np.rot90` before recognition. Therefore record line extraction and rotation explicitly; feeding a multi-column vertical balloon into a 48-pixel-high recognizer is not equivalent to manga-ocr's full-balloon test. Do not mix original Paddle BGR preprocessing with the native RGB safetensors route. [Owning pipeline example](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec_safetensors/blob/485a9a9781535ad477de3b1eea5f96a2e7300d8d/ocr_pipeline.py), [original Paddle configuration](https://huggingface.co/PaddlePaddle/PP-OCRv5_server_rec/blob/b26c3587fda8da3c8ec0ce357214b4d661ff1558/inference.yml).

The Paddle documentation reports CPU normal-mode 21.20 ms/mobile and 31.21 ms/server, on Xeon Gold 6271C, Ubuntu and eight FP32 threads. This supports a CPU experiment, **not Windows latency, manga accuracy or our end-to-end targets**. The official cards and documentation contain differing Japanese accuracy figures/evaluation descriptions; do not rank these models from those percentages. [Paddle recognition documentation](https://www.paddleocr.ai/main/en/version3.x/module_usage/text_recognition.html).

## Hayai Nova: why it is not the first safe experiment

Nova combines SigLIP2 NaFlex vision with a custom 12-layer causal decoder: dimension 512, FFN 2,048, eight query/two KV heads, two-dimensional mRoPE and a 2× spatial projector reducing four patches to one token. Its card advertises crop-level multi-line Japanese/Chinese/Korean/English recognition; 3.65% CER at 384 patches and 3.10% at 512 are **model-author results**, with relative timings on T4 GPU, not independent CPU/Windows measurements. [Owning card](https://huggingface.co/JustANormalTinkerer/hayai-ocr-v2.5-nova), [pinned configuration](https://huggingface.co/JustANormalTinkerer/hayai-ocr-v2.5-nova/blob/2803d0dc005fa4396ab1e7c5a472d2c450a247f7/config.json).

Published loading uses custom `HayaiConfig`/`HayaiModel` through `auto_map` and `trust_remote_code=True`. The source includes CPU FP32/native-BF16 branches and KV-cache decoding, so CPU execution is plausible; Windows speed/RAM are unmeasured. The constructor fetches unpinned Google vision configuration unless supplied locally; fused inference also retains weight copies. Its `generate()` is a custom greedy loop and accepts but ignores beam/repetition-penalty options. A future reviewed, vendored/offline implementation would be necessary before loading, not merely setting `trust_remote_code=False`. [Pinned model source](https://huggingface.co/JustANormalTinkerer/hayai-ocr-v2.5-nova/blob/2803d0dc005fa4396ab1e7c5a472d2c450a247f7/modeling_hayai.py).

Input is RGB processed by Google's standard SigLIP2 NaFlex processor: 16-pixel patches, aspect-preserving dynamic spatial shapes, 1/255 rescale and mean/std 0.5. Pin Google processor revision `b53b807d3a2d5e2b3911292f2d69e5341cdc064c`; **Google's separate 1.5-GB weights are not needed** for Hayai's checkpoint. Nova supplies a standard `PreTrainedTokenizerFast` byte-level BPE tokenizer (16,000 base tokens plus four lowercase special tokens; config vocabulary 16,004). [Pinned Google processor](https://huggingface.co/google/siglip2-base-patch16-naflex/blob/b53b807d3a2d5e2b3911292f2d69e5341cdc064c/preprocessor_config.json), [pinned Nova tokenizer](https://huggingface.co/JustANormalTinkerer/hayai-ocr-v2.5-nova/blob/2803d0dc005fa4396ab1e7c5a472d2c450a247f7/tokenizer.json), [tokenizer config](https://huggingface.co/JustANormalTinkerer/hayai-ocr-v2.5-nova/blob/2803d0dc005fa4396ab1e7c5a472d2c450a247f7/tokenizer_config.json).

The owning helper repo offers LiteRT artifacts for **v2**, not established Nova parity. No Nova ONNX artifact appears in the audited model repository. Do not substitute v2 quantized results for Nova evidence. [Owning helper README](https://github.com/NopeNopeGuy/hayai-ocr).

## Minimum bounded local experiment

1. Prefer installed `TextRecognition` with the pinned native Paddle three-file set, explicit local `model_dir`, model name and CPU. Do not instantiate the full OCR pipeline, optional orientation/document modules or HPI. Validate files before construction; missing assets fail rather than auto-download. Review installed predictor/preprocessor parity and prohibit output-image saving.
2. Explicitly acquire only these data files into a gitignored comparator folder and independently hash all bytes. If native loading is incompatible, stop or isolate a reviewed environment. A future Transformers route uses local safetensors/config/processor with `local_files_only=True`, `trust_remote_code=False`, CPU FP32 and `eval()`; no production framework upgrade or remote Python.
3. Sanity-check authored horizontal/vertical lines, empty inputs and repeated characters. Then use the frozen eligible private crops entirely offline, in RAM. Preserve original labels and separately flag unresolved labels. Do not use original-label information to select orientation or crop transformation.
4. Report unchanged full-balloon results and the **separate line/column reconstruction route**; record geometry, order, rotation, CER/exact match and difficult categories. Line extraction errors are pipeline errors, not invisible recognizer exclusions. A score threshold cannot silently remove uncertain text.
5. Measure cold load, three warm passes, actual threads, peak process RSS and per-crop/page time on the target Windows CPU. Retain raw punctuation/expressive spacing; metric normalization is not production cleanup. Test server only if the mobile route is promising. No cloud, release/default change, new large dataset or perfect-quality claim follows from this note.
