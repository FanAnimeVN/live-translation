# Competitor delivery evidence — 2026-10-16

Scope: public primary-source research, not a benchmark or a production change. No model/data downloads, installs, paid calls or private-image uploads. Public source text was read transiently in memory. `AGENTS.md` and the research skill were read.

## What the sources establish

1. **Repeated reading can reuse prior work.** Scan Translator says an already translated image in the same target language incurs no new credit, including a translation previously made by another user. It also says its service incurs paid third-party service/infrastructure costs. This documents reuse and a service-backed workflow; it does not identify its OCR/translation models or establish cache-hit latency. [Official FAQ](https://scan-translator.com/faq).

2. **Recovery has separate entry points.** Scan's August 2026 Retry reruns translation and generates a new image without repeating detection, at one credit. Missed text instead uses Screenshot. Its June update allows Screenshot patches alongside auto translation and clears those patches when leaving the page. The FAQ acknowledges missed/merged/untranslated text and overflow/misalignment. These are documented failure accommodations, not evidence of perfect recognition. [Updates](https://scan-translator.com/updates), [FAQ](https://scan-translator.com/faq).

3. **Kites processes and returns a completed image.** At `4acebe6dd3bd253aafaf38b24d849f9b40ba94e0`, it decodes the source image dimensions, runs OCR, optionally runs translation and inpainting concurrently, measures/fits bubble layout, renders translated text onto the cleaned canvas, then returns a baked image. Translation failure can fall back to OCR text and inpaint failure to the original image; successful completion alone is therefore not proof of successful translation or cleaning. [Pinned pipeline, lines 119–368](https://github.com/Unheat/Kites/blob/4acebe6dd3bd253aafaf38b24d849f9b40ba94e0/src/offscreen/services/PipelineOrchestrator.ts#L119-L368).

4. **Kites' automatic mode is image/visibility driven.** The pinned content script uses `IntersectionObserver` to queue visible images and avoids already queued sources. It also reapplies an existing session translation when a reader restores the raw image. This is not evidence of per-frame OCR, unlimited chapter pretranslation, or a particular numeric prefetch budget. Chapter batching/preloading is a separate path; its complete resource bounds were not audited here. [Pinned content script](https://github.com/Unheat/Kites/blob/4acebe6dd3bd253aafaf38b24d849f9b40ba94e0/src/content/index.tsx).

5. **Comic Translate's improvement is the surrounding pipeline too.** Its official README lists RT-DETR-v2 bubble/text detection plus algorithmic segmentation, **manga-ocr as default Japanese OCR**, LaMa/AOT cleaning, whole-page text supplied to the translator with optional image context, and wrapped lettering. It lets users read completed pages while other images process and offers Undo/Manual Mode for failed detection, OCR or cleaning. The README advertises desktop and Chromium products; this inspection does not establish that all commercial extension code is included in the public repository. [Official README](https://github.com/ogkalu2/comic-translate#how-it-works).

6. **manga-image-translator is a complete batch/server reference.** The pinned README supports input folders/files, local batch and CPU web-server operation, separate render/inpaint options, and page-context options for its OpenAI translator. It documents font/bubble fitting and source-text leakage as tunable problems, and warns large inpaint sizes can exhaust memory. CPU support is not proof of acceptable CPU latency. [Pinned README](https://github.com/zyddnys/manga-image-translator/blob/d6de6ab62a7be6afc0d07a3184149cdefbcd32f2/README.md).

## Which open-source solution fits this project

Updated decision after reader review: use **manga-image-translator as the primary complete-pipeline comparator**, **Comic Translate as the secondary comparator/permissive integration candidate**, and **Kites only as an optional extension UX reference**. Repository stars are an adoption signal, not OCR, Vietnamese quality or latency evidence. Compare complete pipelines on the existing private gold set before choosing components. No inspected source proves superiority on this 16 GB Windows machine.

## Interpretation and limits

- **Inference to test:** usable reading can come from page-level coverage/context, cleaning + fitted lettering, reuse of completed results, queued work while reading, and targeted recovery. A weak end-to-end baseline cannot be diagnosed solely by naming its OCR model. Neither the sources nor this research provide a controlled causal comparison against our current build.
- **Unknown:** Scan's proprietary engine/model mix, private quality metrics, actual cache implementation and target-machine latency. There is no evidence here that its extension depends on human proofreading or manual labour. Scanlation publication workflows do not establish commercial extension internals.
- **No generic detector promotion:** the earlier internal audit recommends detector candidates, but is secondary evidence, not new results. Prior block-guide experiments already had regressions. Recheck full-pipeline coverage, merges, crop contamination, translation, protected art, lettering and latency together; do not flip another default from README claims. [Internal detector audit](detector-alternatives-20261014.md), [internal pinned grouping audit](utterance-pipeline-research-20261016.md).
- **Bounded next comparison:** frozen private pages and audited gold; source/engine/revision recorded; full-page coverage and difficult cases retained; same hardware; cold/warm timing and peak RAM; current page/cutoff/locks and exact original restoration checked. No expansion to another dataset or paid route is implied.
- **Privacy/rights unchanged:** RAM-only images, no offline cloud/metadata requests, existing consent/cost gates and reader locks remain required. Competitor image persistence, shared reuse, or inpainting defaults are not permission to adopt them here. This note makes no release, speed, accuracy or mobile-readiness claim.
